Agents & Tool Use — 5 topics

  1. The agentic loop

    Instead of one call returning an answer, the model is given tools and asked what to do next. It requests a tool call, your code runs it and feeds the result back, and this repeats until the model answers. The loop is the whole idea; everything else is plumbing.

  2. Designing tools

    A tool is a name, a description and a JSON schema — and the model picks it based on that description alone, so the description is the prompt. Few well-named tools beat many overlapping ones, and every tool needs to return errors the model can act on.

  3. Multi-step reasoning & planning

    Chain-of-thought, ReAct-style interleaving of reasoning and action, and explicit plan-then-execute. The practical question is how much autonomy to give: more steps means more capability and more ways to go wrong, so bound the loop.

  4. Multi-agent orchestration

    Splitting work across specialised agents — a researcher, a writer, a critic — with explicit handoffs and shared state. Genuinely useful for separable tasks, and frequently over-applied where one well-prompted agent would do.

  5. Failure modes & guardrails

    Agents loop forever, call the same tool repeatedly, hallucinate arguments, and act on untrusted input — prompt injection through retrieved content is a real attack, not a theoretical one. Step limits, schema validation, sandboxing and human approval for destructive actions are the defences.
