Production & Evaluation — 5 topics

  1. Provider routing & fallback

    Depending on one provider means their outage is your outage, and their rate limit is your ceiling. A router in front of several — with a consistent interface and a fallback order — turns that into a degraded response instead of a failure.

    Resources
    Learn
    • LiteLLM docs — routing, fallbacks, cost tracking
    • AWS — retries with jitter
    • Fowler — circuit breaker
    Practice
    • Kill your primary provider key and confirm the app degrades instead of erroring.
    My code
    • lenny-growth-assistant — LiteLLM fallback across OpenAI, Gemini, Claude and Ollama

  2. Running local models

    Ollama makes running Llama or Mistral locally genuinely easy, which matters for privacy, offline work and cost. The trade is quality and speed — and being able to swap cloud for local behind one config is a strong engineering signal.

    Resources

    Practice

    My code

    • oogway — the same assistant lineage

  3. Cost & latency

    Cost is tokens in plus tokens out, and latency is dominated by output length. The levers, in order: send less context, cache prompts, stream so time-to-first-token feels fast, and route simple requests to a cheaper model.

    Resources
    Learn
    • Claude — prompt caching
    • OpenAI — latency optimisation
    • LiteLLM — per-request cost tracking
    Practice
    • Instrument one endpoint for tokens and cost per request, then cut it by 30%.
    My code
    • lenny-growth-assistant — streaming responses

  4. Evaluation & regression testing

    Prompts are code without a test suite unless you build one. A golden set plus automated scoring turns "this feels better" into evidence, and catches the regression where fixing one case quietly breaks five others.

    Practice

  5. Observability for LLM apps

    Standard metrics plus LLM-specific ones: tokens, cost, latency per stage, retrieval hit-rate, refusal and error rates. Tracing a full agent run — every prompt, tool call and result — is the only practical way to debug one.
