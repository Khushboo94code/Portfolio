RAG — 6 topics

  1. The RAG pipeline end to end

    Two halves: an offline ingest path that chunks and embeds documents into a vector store, and an online query path that embeds the question, retrieves the closest chunks, and puts them in the prompt. Both sides must use the same embedding model.

  2. Chunking strategy

    The most under-rated decision in RAG. Chunks too large bury the answer in noise and waste context; too small and they lose the context that makes them meaningful. Overlap preserves meaning across boundaries, and splitting on document structure beats splitting on character count.

    Resources
    Learn
    • LlamaIndex — node parsers & chunking
    • LangChain — text splitters
    • RAG paper — the retrieval unit matters
    Practice
    • Try three chunk sizes on the same corpus and measure retrieval hit-rate for each.

  3. Vector search & ANN indexes

    Exact nearest-neighbour search is O(n) and fine until it is not. Approximate indexes — HNSW, IVFFlat — trade a little recall for a large speed win, and each has parameters that move that trade. Keeping vectors in Postgres avoids running a second database.

    Resources

    Practice

  4. Hybrid search & reranking

    Embeddings miss exact matches — product codes, names, rare terms — which keyword search nails. Hybrid retrieval runs both and fuses the results; a reranker then scores the merged candidates properly. This is usually the largest single quality win available.

  5. Grounding, citations & hallucination

    Retrieval alone does not stop a model inventing things — the prompt must instruct it to answer only from the provided context and to say when the context is insufficient. Returning citations is what makes an answer auditable rather than merely confident.

    Resources

    Practice

  6. Evaluating a RAG system

    You cannot improve what you do not measure, and "it looks good" is not measurement. Evaluate the two stages separately: retrieval by hit-rate and MRR against a golden set, generation by groundedness and answer correctness. Otherwise you cannot tell which half is broken.
