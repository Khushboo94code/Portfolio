Async & the Event Loop — 5 topics

  1. The event loop

    A single thread running a queue of ready tasks. It runs one coroutine until that coroutine hits an await, parks it while the I/O is outstanding, and picks the next ready task. There is no preemption at all — cooperation is the entire model.

  2. Coroutines, await & tasks

    async def defines a coroutine that does nothing until awaited or scheduled. await on one coroutine is still sequential — concurrency only starts when you create tasks or use gather, which is the mistake almost everyone makes first.

  3. Blocking the loop

    The cardinal sin. One synchronous call — time.sleep, requests.get, a sync database driver, a heavy computation — freezes every task in the process, because nothing can preempt it. The fixes are an async library, or run_in_executor to push it to a thread or process.

  4. Async in web frameworks

    FastAPI is async-first; Django supports async views under ASGI with sync_to_async bridging the ORM. The trap is a sync database call inside an async view — it blocks the loop and makes the app slower than the sync version would have been.

  5. Cancellation, timeouts & errors

    Async tasks can be cancelled, and cancellation arrives as an exception you must let propagate. Every external call needs a timeout; gather hides failures unless you ask for them, and an un-awaited task that raises fails silently.
