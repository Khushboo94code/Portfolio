  1. Processes & process pools

    The way past the GIL. ProcessPoolExecutor mirrors the thread pool API, so switching between them is often one word — but every argument and return value has to cross a process boundary, which is not free.

  2. Pickling & what can cross a boundary

    Arguments and results are serialised with pickle, so lambdas, open sockets, database connections and local closures cannot travel. Most confusing multiprocessing errors are really pickling errors — and large arguments make the copy itself the bottleneck.

  3. IPC — queues, pipes & shared memory

    Processes talk through multiprocessing.Queue, pipes, or genuinely shared memory for large arrays. Shared memory is fastest and reintroduces every synchronisation problem isolation had removed — use it only when copying is measurably the bottleneck.

  4. fork vs spawn

    Start methods differ by platform and change behaviour: fork copies the parent process and is fast but unsafe alongside threads; spawn starts fresh and re-imports your module, which is why multiprocessing code needs the if __name__ == "__main__" guard.
