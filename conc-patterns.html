Patterns & Production — 5 topics

  1. Producer-consumer

    The most useful concurrency pattern there is: producers put work on a bounded queue, consumers take it off, and the queue decouples their speeds. A bounded queue also gives you backpressure for free — producers block when consumers fall behind.

  2. Worker pools & task queues

  3. Backpressure & bounded resources

    Unbounded queues do not remove overload, they hide it until you run out of memory. Bounding a queue makes the pressure visible and forces a decision: block the producer, shed load, or scale consumers. Connection pools are the same idea.

  4. Testing concurrent code

    Race conditions are nondeterministic, so a passing test proves very little. The practical answers: make the concurrency injectable so tests can run it serially, stress the hot path in a loop, and use timeouts so a deadlocked test fails instead of hanging CI forever.

  5. Debugging & observability

    Concurrent failures are the hardest to reproduce, so instrumentation matters more than usual. Log the thread or task id on every line, use faulthandler to dump stacks from a hung process, and remember the standard logging module is thread-safe by design.
