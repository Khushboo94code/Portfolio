Performance — 5 topics

  1. Indexes & B-trees

    An index is a sorted structure that turns a full scan into a lookup. B-tree serves equality and range; hash only equality; GIN and GiST handle full-text and arrays. Composite index order follows the leftmost-prefix rule, and every index you add slows writes.

  2. EXPLAIN & the query planner

    The planner estimates costs and picks a strategy; EXPLAIN ANALYZE shows what it actually did. Learn to spot a sequential scan on a large table, a mis-estimated row count, and a nested loop that should have been a hash join.

  3. Query optimisation patterns

    The recurring wins: replace correlated subqueries with joins, avoid functions on indexed columns in WHERE, select only the columns you need, paginate by cursor rather than OFFSET on large tables, and fix N+1 at the ORM layer rather than the SQL one.

  4. Denormalisation, views & caching

    When reads outgrow a clean schema: materialised views precompute expensive aggregates, denormalised columns trade write complexity for read speed, and a cache in front trades freshness for both. Each one is a correctness trade you should state out loud.

  5. Partitioning & scaling reads

    Splitting one large table by range or list so queries touch less data, and read replicas for spreading read load. Both have real costs — cross-partition queries and replication lag — which is why they come after indexing, not before.
