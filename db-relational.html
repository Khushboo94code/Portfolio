Relational Foundations — 5 topics

  1. The relational model & keys

    Data as tables of rows, related by values rather than pointers. Primary keys identify a row uniquely, foreign keys reference one, and candidate keys are the alternatives you did not pick. Natural versus surrogate keys is the first real design argument you will have.

  2. Normalization — 1NF to BCNF

    Removing redundancy so one fact lives in one place: 1NF atomic values, 2NF no partial dependency on a composite key, 3NF no transitive dependency, BCNF the strict form. The point is not purity — it is that redundant data drifts out of sync.

  3. ER modelling

    Entities, attributes and relationships — and the cardinalities between them. One-to-many becomes a foreign key; many-to-many becomes a join table. Drawing this before writing DDL is what stops you discovering a missing relationship three migrations later.

  4. Constraints & integrity

    Rules the database enforces so bad rows cannot exist even when application code has a bug: NOT NULL, UNIQUE, CHECK, foreign keys and their ON DELETE behaviour. A constraint is a guarantee; a model validator is only a request.

  5. Schema design in practice

    Where theory meets deadlines: choosing types deliberately (never float for money), naming consistently, soft deletes versus hard, storing timestamps in UTC, and designing for the queries you will actually run rather than for elegance.
