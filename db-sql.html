SQL — 6 topics

  1. SELECT, filtering & ordering

    The clause execution order is the thing worth internalising: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT. It explains why you cannot use a SELECT alias in WHERE but can in ORDER BY, which confuses people for years.

  2. Joins

    INNER, LEFT, RIGHT, FULL and CROSS — plus the self-join, which is how you compare rows in the same table. The interview favourite is "find rows with no match", which is a LEFT JOIN with an IS NULL filter, or a NOT EXISTS.

  3. Aggregation & GROUP BY

    COUNT, SUM, AVG, MIN, MAX collapsed by group — and the distinction that trips everyone: WHERE filters rows before grouping, HAVING filters groups after. COUNT(*) and COUNT(column) differ on NULLs, which is a real bug source.

  4. Subqueries & CTEs

    A subquery nests a query inside another; a CTE (WITH) names it so the whole thing stays readable. Correlated subqueries run per row and are often the slow path — and recursive CTEs are how you walk a tree in SQL.

  5. Window functions

    Aggregate across a set of rows without collapsing them — ROW_NUMBER, RANK, DENSE_RANK, LAG, LEAD, and running totals with SUM OVER. This is the single highest-leverage SQL feature and the one that separates comfortable from expert.

  6. DML, DDL & upserts

    INSERT, UPDATE, DELETE, and the schema side — CREATE, ALTER, DROP. Plus INSERT ... ON CONFLICT, which is how you write an idempotent upsert, and why a DELETE without a WHERE is the most expensive keystroke in the industry.
