  2. Isolation levels & anomalies

    Read uncommitted, read committed, repeatable read, serializable — and the anomalies each permits: dirty reads, non-repeatable reads, phantoms and write skew. Postgres defaults to read committed, which allows more than people assume.

  3. Locking & MVCC

    Postgres uses multi-version concurrency control, so readers never block writers and writers never block readers — a very different model from lock-everything databases. Explicit SELECT ... FOR UPDATE is how you serialise a row when you actually need to.

  4. Deadlocks in the database

    Two transactions each holding what the other needs. Postgres detects the cycle and kills one with SQLSTATE 40P01 — so your application must be ready to retry. Consistent ordering of updates is the prevention.
