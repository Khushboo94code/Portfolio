Automation & CI/CD — 4 topics

  1. Deploying from git

    The deploy artefact should be a specific commit, not "whatever is on the server". Push to a branch, have the platform build and release that exact SHA, and keep the previous release so you can go back.

  2. CI — testing before you ship

    Run the test suite, linting and check --deploy on every push, and block merges that fail. The value is not the tests themselves but that nobody has to remember to run them.

  3. Deploying containers

    Build the image once, tag it by commit SHA, push it to a registry, and deploy that digest. The point is that the artefact you tested is byte-for-byte the artefact that runs.

    Resources

  4. Zero-downtime releases

    Rolling, blue-green and canary — all answers to "how do I replace running code without dropping requests". They all require that the old and new versions can run at once, which is why backwards-compatible migrations come first.
