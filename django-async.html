Async & Caching — 4 topics

  1. Celery task design

    Moving slow work off the request cycle. The design rules are the distributed-systems ones: tasks should be small, idempotent and retryable, arguments should be IDs rather than objects, and every task needs a defined failure path.

  2. Periodic tasks & scheduling

    Celery beat for recurring work, with schedules as configuration rather than code. Two things bite in production: overlapping runs when a job outlasts its interval, and more than one beat process firing the same schedule — both need a lock.

    Resources

    Practice

  3. Caching layers in Django

    Django gives you four levels — per-site, per-view, template fragment and the low-level cache API — and the low-level one is where real work happens. The hard part is the same as in HLD: invalidation, and choosing a key scheme you can reason about.

  4. Async views, ASGI & Channels

    Django's async story: async def views under ASGI, sync_to_async and the ORM's async API, and Channels for WebSockets. Worth knowing what async actually buys — concurrency on I/O waits, not faster CPU-bound code.
