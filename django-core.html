Core Django — 6 topics

  1. MVT & the request/response cycle

    What actually happens between a request arriving at WSGI and a response going out: URL resolution, middleware on the way in and out, the view, then rendering. Knowing this order is what lets you answer "where should this logic live?" with something other than a guess.

    Resources
    Learn
    • Django — handling HTTP requests
    • Django official tutorial — still the best starting point
    • Adam Johnson's Django blog — deep, practical, consistently correct
    Practice
    • Trace one request end to end with django-debug-toolbar and list every middleware it passes through.
    My code
    • instahyre — a full Django app, front to back

  2. Models & the ORM

    Modelling your domain as tables without writing SQL: field types, relationships (ForeignKey, ManyToMany, OneToOne), related_name, and model methods. This is where the data-modelling half of HLD actually gets expressed.

    Resources
    Learn
    • Django — models
    • Django — model field reference
    • Django ORM Cookbook — recipe per question
    Practice
    • Model a marketplace (vendors, products, orders, payouts) and justify every relationship type.
    • Combine Two Tables — the SQL a select_related join generates
    My code
    • Digital-market-place-app — vendor / product / order modelling
    • instahyre — job-board domain model

  3. Migrations

    Schema change as versioned, reviewable code. The skill worth having is the zero-downtime kind: expand, migrate data, then contract — so old and new code can run against the same database during a deploy. Data migrations and RunPython belong here too.

    Resources
    Learn
    • Django — migrations
    • Django — writing migrations
    • django-migration-linter — catches backwards-incompatible migrations
    Practice
    • Rename a column on a live app with zero downtime using add → backfill → switch → drop.
    • Write a data migration that backfills a new field, and make it re-runnable.
    My code
    • Digital-market-place-app — migration history of a real schema

  4. Views — FBV, CBV & generics

    Function views are explicit; class-based views trade that for reuse through mixins and a fixed method flow. Knowing the CBV method resolution order — dispatch, get_queryset, get_context_data — is what makes generic views predictable rather than magic.

    Resources
    Learn

    • Django — CBV reference
    Practice

    My code

  5. URLs, forms & templates

    Routing with path converters and namespaces, forms as the validation boundary for untrusted input, and template inheritance with autoescaping. Forms matter more than they look — validation belongs at the edge, not scattered through views.

    Resources
    Learn

    My code

    • instahyre — forms and templates in context

  6. The Django admin

    A free internal tool, and genuinely a competitive advantage when you customise it rather than just register models — list_select_related to kill N+1s, custom actions, inlines, and read-only fields. Worth knowing its limits, too: it is not a customer-facing UI.

    Practice
