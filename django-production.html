Architecture & Production — 6 topics

  1. Settings, environments & secrets

    Config as environment, not as committed code. Split settings per environment, read secrets from the environment or a vault, and never let DEBUG=True or a real SECRET_KEY reach a repository.

  2. Project structure & the service layer

    Where business logic lives once views and models both get too fat. A service layer keeps domain rules callable from a view, a Celery task, a management command or a test — which is the same dependency-inversion argument as in LLD, applied to a Django project.

  3. Signals, middleware & the request pipeline

    Django's two extension points, and when each is a mistake. Middleware is genuinely cross-cutting — request IDs, timing, auth. Signals are the observer pattern, and they make control flow hard to follow; an explicit service call is usually better.

  4. Security in Django

    What the framework gives you free — CSRF protection, ORM parameterisation against SQL injection, template autoescaping — and what it doesn't: CSP, secure cookie flags, HSTS, rate limiting, and never trusting file uploads.

  5. Deployment topology

    The standard shape: Nginx terminating TLS and serving static files, Gunicorn running the WSGI workers, Postgres and Redis behind them, all containerised. Static and media are the part people get wrong — collectstatic to a CDN, media to object storage.

  6. Scaling Django

    Where a Django app actually breaks under load, and in what order: database connections first (use a pooler), then N+1s, then synchronous third-party calls. Read replicas need a database router; horizontal scaling needs the statelessness from the HLD track.
