Compose & Multi-Service — 4 topics

  1. Docker Compose basics

    One YAML file describing every service, its image or build context, ports, volumes and networks — then docker compose up brings the stack up together. This is what makes a project cloneable and runnable in one command.

  2. Dependencies & healthchecks

    depends_on only waits for the container to start, not to be ready — which is why Django so often crashes on boot because Postgres is still initialising. condition: service_healthy plus a HEALTHCHECK is the actual fix.

  3. Development vs production compose

    The same stack needs different shapes: bind mounts and auto-reload locally, baked images and no source mount in production. Override files (compose.override.yml) and profiles keep that in one place instead of two divergent files.

  4. Running migrations & one-off jobs

    Where migrate and collectstatic actually belong — not in the image build, where there is no database, and not racing across multiple replicas at boot. An explicit entrypoint step or a one-off compose run is the safe pattern.
