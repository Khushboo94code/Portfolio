Data & Networking — 4 topics

  1. Volumes & bind mounts

    A container’s writable layer dies with it, so anything that must persist needs a volume. Named volumes are managed by Docker and right for databases; bind mounts map a host directory in and are right for live-reloading source in development.

  2. Networks & service discovery

    Containers on a user-defined bridge network reach each other by service name — Docker runs an embedded DNS resolver. This is why db works as a hostname in Compose and why the default bridge network is not good enough.

    Resources

  3. Ports, publishing & EXPOSE

    EXPOSE is documentation only — it publishes nothing. -p 8000:8000 is what actually maps a host port to a container port. Binding to 127.0.0.1 inside the container is the classic reason a published port still refuses connections.

  4. Environment variables & secrets

    Configuration belongs in the environment, not the image — but environment variables are visible in docker inspect and in your shell history, so real secrets need Docker secrets, a mounted file, or a vault. Never bake a key into a layer; layers are forever.
