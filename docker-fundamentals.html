Fundamentals — 5 topics

  1. Containers vs virtual machines

    A container is a process on the host kernel with namespaces for isolation and cgroups for limits — not a virtual machine. That is why it starts in milliseconds and why a Linux container cannot run on a Windows kernel without a VM underneath.

    Resources
    Learn
    • Docker — overview & architecture
    • Linux namespaces — Wikipedia — the isolation primitive
    • cgroups — Wikipedia — the resource-limit primitive
    Practice
    • Run a container and find its process on the host with ps aux — prove it is just a process.

  2. Images, layers & the union filesystem

    An image is a stack of read-only layers; a container adds one writable layer on top. Every Dockerfile instruction creates a layer, layers are cached and shared between images, and that sharing is why a second image built on the same base is nearly free.

    Resources
    Learn
    • Docker — build cache & layers
    • Dockerfile reference
    • dive — inspect an image layer by layer
    Practice
    • Run docker history on one of your images and account for the size of every layer.

  3. Writing a Dockerfile

    The instruction set and what each one costs: FROM, RUN, COPY, WORKDIR, ENV, EXPOSE, and the difference between CMD and ENTRYPOINT — entrypoint is the binary, cmd is the default arguments.

  4. Registries, tags & digests

    Pushing and pulling from Docker Hub or ECR, and why :latest is a trap — it is just a mutable tag, so a rebuild can silently change what deploys. Digests (@sha256:…) are the only truly immutable reference.
