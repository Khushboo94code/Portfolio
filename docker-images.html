Image Quality — 4 topics

  1. Layer caching & build speed

    Docker caches each layer and invalidates everything after the first change — so COPY . . before pip install means every source edit reinstalls all dependencies. Copy the requirements file first, install, then copy source.

  2. Multi-stage builds

    Build in one stage with compilers and dev headers, copy only the artefact into a clean runtime stage. Shrinks images dramatically and removes the build toolchain from what you ship — which is a security win as much as a size one.

  3. Base images & image size

    Choosing between python:3.12, -slim and Alpine. Alpine is smallest but uses musl instead of glibc, which breaks some Python wheels and can make builds slower — slim is usually the right default.

  4. .dockerignore & reproducibility

    Without a .dockerignore, your build context ships .git, .venv, node_modules and local .env files into the daemon — slow, bloated, and a genuine secret-leak risk. Pinning versions is the other half of a reproducible build.
