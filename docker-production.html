Production — 5 topics

  1. Logging & debugging containers

    Containers log to stdout/stderr and Docker collects it — so never write to a log file inside a container. docker logs -f, exec into a running container, and inspect for the full config are the three tools you need when something is wrong.

  2. Resource limits & the OOM killer

    Without --memory and --cpus, one runaway container can take down its host. Exceeding a memory limit gets the process SIGKILLed — exit code 137, the single most common mystery container death.

  3. Container security

    Run as a non-root user — the default is root, and root in the container is root on the host if anything escapes. Then: pin base image versions, scan for CVEs, drop capabilities, and use read-only filesystems where you can.
