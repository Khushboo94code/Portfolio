Fundamentals — 5 topics

  1. The three trees

    Working directory, staging area (index) and repository. Every command moves changes between these three — add working→staging, commit staging→repository, restore back again. Almost all git confusion is not knowing which tree a command touches.

  2. Commits, SHAs & history

    A commit is an immutable snapshot with a parent pointer, identified by a hash of its content. History is therefore a directed graph, not a list — which is why rebasing creates new commits rather than moving existing ones.

    Resources

  3. Branches as pointers

    A branch is a movable pointer to a commit, and nothing more — which is why creating one is instant and free. HEAD points at your current branch; "detached HEAD" just means it points directly at a commit instead.

  4. Remotes & tracking branches

    origin/main is your local cache of where the remote was at last fetch — not where it is now. fetch updates that cache, pull is fetch plus merge. Knowing the difference explains most "why is it out of date" confusion.

    Resources
    Learn
    • Pro Git — remote branches

    • Command reference — fetch, pull, push
    Practice
    • Fetch without pulling, then diff your branch against origin/main.

  5. .gitignore & what not to commit

    Secrets, virtualenvs, __pycache__, build output and large binaries. The important part: adding something to .gitignore after committing it does nothing — it is still in history, and a committed credential must be rotated, not just deleted.
