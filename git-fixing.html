Fixing Mistakes — 4 topics

  1. reset vs revert vs restore

    Three different tools people confuse. restore discards file changes, reset moves the branch pointer and rewrites history, revert adds a new commit undoing an old one. On anything already pushed, revert is the safe choice.

  2. Recovering with reflog

    git reflog records every position HEAD has held, including commits no branch points at any more. A "lost" commit after a bad reset or a deleted branch is almost always still there for weeks — this is the command that saves you.

    Resources
    Learn
    • git reflog — docs
    • Pro Git — data recovery
    • Command reference — recovery row
    Practice
    • Delete a branch, then recover it from the reflog.
    • Do a reset --hard you regret, then undo it.

  3. Rewriting history

    commit --amend for the last commit, interactive rebase to squash, reorder or reword several. Fine on your own unpushed branch; disruptive on a shared one, and --force-with-lease is the safer force push.

  4. Stash, clean & bisect

    stash parks work in progress so you can switch branches; clean removes untracked files; bisect binary-searches your history to find the commit that introduced a bug — which turns an afternoon of guessing into about eight checkouts.
