GitHub — 5 topics

  1. Pull requests & review

    A PR is a request to merge plus a place to discuss it. Small PRs get reviewed properly and large ones get rubber-stamped, so keep them focused. Write the description for someone who was not in your head when you wrote the code.

    Resources
    Learn
    • GitHub — pull requests
    • Google — code review practices — both sides of it
    • GitHub — about PRs
    Practice
    • Open a PR on one of your own repos and review it as if it were someone else’s.

  2. GitHub Actions

    CI/CD built into the repo: workflows triggered by pushes, PRs or schedules, running tests, building images, deploying. The free tier is generous, and a green check on every PR changes how a repo reads to anyone looking at it.

    Resources

  3. Protecting main

    Branch protection rules: require a passing CI run, require a review, block force pushes. On a solo project this feels like bureaucracy until the first time it stops you pushing a broken migration straight to main.

    Resources
    Learn

  4. Issues, projects & releases

    Issues track work and link to the commits that close them; releases tag a version with notes and artefacts. Semantic versioning tells consumers whether an upgrade can break them.

  5. Your repo as portfolio

    For you specifically this matters more than average: your GitHub is the evidence behind your résumé. A README that states the problem, the approach and how to run it — plus a screenshot or demo link — is the difference between a repo someone opens and one they skim past.
