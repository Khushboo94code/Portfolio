  1. Feature branch workflow

    Branch off main, commit small and often, push, open a pull request, merge. Short-lived branches are the whole trick: a branch open for three weeks is a merge conflict with a countdown timer.

  2. Merge vs rebase

    Merge preserves history exactly and adds a merge commit; rebase replays your commits on top of the target for a linear history but rewrites them. The rule worth memorising: never rebase a branch someone else has pulled.

  3. Resolving conflicts

    A conflict is git saying two people changed the same lines and it will not guess. Read both sides, keep what is correct rather than what is yours, remove the markers, test, then continue. Panic is the only real failure mode here.

  4. Commit hygiene

    One logical change per commit, and a message saying why rather than what — the diff already shows what. Conventional Commits gives a format; add -p is how you split messy work into clean commits.
