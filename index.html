Lenny — Full-Stack Agentic AI Assistant

2026

An assistant that takes actions and cites its sources, without being locked to one LLM provider.

  • Built an agentic loop with tool / function calling (Claude Agent SDK) so the assistant takes actions, not just answers, with a LiteLLM fallback for reliability.
  • Implemented RAG over pgvector with grounded, cited answers over a knowledge base.
  • Ran cloud and fully-local LLMs (OpenAI, Gemini, Claude, and Llama 3.1 via Ollama), swappable via one config.
  • Added custom command skills and output guardrails (sanitised HTML, sandboxed iframe + CSP); Dockerized end to end.

Architecture

React UI → FastAPI → Agent loop
(Claude Agent SDK) → Tools / skills Retriever → pgvector → LiteLLM router → OpenAI · Gemini · Claude Ollama (Llama 3.1, local)

Key decisions

  • Agentic loop over a single call — the model plans, calls a tool, reads the result and continues, so it can act rather than only answer.
  • Provider abstraction via LiteLLM — one config swaps cloud for fully-local models, and gives a fallback path when a provider fails or rate-limits.
  • One Postgres for both — relational data and vectors live in the same database, avoiding a separate vector store to operate.
  • Output guardrails — model output is sanitised HTML rendered in a sandboxed iframe under a CSP, so generated markup can't execute against the app.

Q-Commerce Price Intelligence Dashboard

June 2026

Continuously collect competitor pricing at scale without getting blocked or losing data.

  • Built Scrapy crawlers + Celery/Redis scheduling to continuously collect competitor pricing at scale, with throttling, retries and error handling.
  • Exposed REST APIs powering price comparison, filtering and historical pricing insights on a live dashboard.

Architecture

Celery beat
(schedule) → Redis queue → Scrapy workers → Normalise → PostgreSQL
(price history) → DRF API → Dashboard

Key decisions

  • Queue-backed workers — crawling is decoupled from the API, so a slow or failing target never blocks a user request.
  • Throttling and retries with backoff — keeps crawls polite and survives transient failures instead of dropping a run.
  • Append-only price history — every observation is stored with a timestamp, which is what makes historical trend queries possible later.
  • Scheduling in Celery beat — collection cadence is configuration, not code, so different sources can run at different frequencies.

Multi-Vendor Digital Marketplace

2026

Many sellers, real money, and paid files that must not leak.

  • Built and deployed a role-based marketplace with secure Stripe Connect payments, S3 pre-signed downloads, and full vendor / customer / admin workflows.

Architecture

Nginx → Gunicorn / Django → PostgreSQL Redis + Celery Stripe Connect S3 pre-signed URLs

Key decisions

  • Stripe Connect for split payments — money routes to vendors through Stripe, so the platform never has to hold or reconcile balances itself.
  • Pre-signed S3 downloads — paid files are served straight from S3 with a short-lived signed URL, keeping large downloads off the app servers and links unshareable.
  • Role-based access — vendor, customer and admin permissions enforced at the API layer rather than hidden in the UI.
  • Celery for the slow path — emails, webhooks and post-purchase work happen off the request cycle.
