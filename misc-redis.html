Keys & expiry

Never run KEYS * on a real instance — Redis is single-threaded and it blocks everything. SCAN is the safe iterator.

CommandDoes
SET k vSet a string value
GET kRead it
DEL kDelete a key
EXISTS kDoes it exist
EXPIRE k 60Expire in 60 seconds
TTL kSeconds left (-1 no expiry, -2 gone)
PERSIST kRemove the expiry
SCAN 0 MATCH u:*Safe cursor iteration over keys
TYPE kWhich data type this key holds
RENAME k k2Rename a key

Hashes

Use these when a key holds an object — you can update one field without rewriting the whole thing.

CommandDoes

HGET k fieldRead one field
HMGET k f1 f2Read several fields
HGETALL kRead every field — careful on large hashes
HDEL k fieldDelete a field
HINCRBY k field 1Atomically increment a field
HEXISTS k fieldDoes the field exist
HKEYS k / HVALS kAll field names / all values

Sorted sets

The most useful type in Redis — leaderboards, priority queues, sliding-window rate limiters and time indexes are all this.

CommandDoes
ZADD k 100 memberAdd with a score
ZINCRBY k 10 memberAtomically bump a score
ZSCORE k memberRead a score
ZRANK k memberRank ascending; ZREVRANK descending
ZRANGE k 0 9 REVTop 10 — the leaderboard query
ZRANGEBYSCORE k 100 200Everything in a score range
ZREMRANGEBYSCORE k 0 tDrop old entries — the sliding window trim
ZCARD k / ZCOUNT k min maxCount all / count in range

Pub/sub & streams

Pub/sub does not persist — an offline subscriber misses the message. Streams do, with acknowledgement and replay.

CommandDoes
PUBLISH ch msgBroadcast to subscribers
SUBSCRIBE chListen on a channel
PSUBSCRIBE news.*Pattern subscribe
XADD s * field vAppend to a stream
XREAD COUNT 10 STREAMS s 0Read from a stream
XGROUP CREATE s grp 0Create a consumer group
XACK s grp idAcknowledge a processed message
