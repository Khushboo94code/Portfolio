Using It Well — 5 topics

  1. When a class is the wrong tool

    A class with one method and no state is a function. A class whose __init__ takes everything and whose methods only read it is a function with extra steps. The test is whether there is state that several methods genuinely share and protect — if not, write the function.

    Resources
    Learn
    • Jack Diederich — Stop Writing Classes (PyCon 2012)
    • PEP 20 — The Zen of Python
    Practice
    • Find a class in your code with one method and collapse it to a function.
    • Count how many of your classes have more than two methods that touch the same attribute.

  2. dict, NamedTuple, dataclass or class?

    Four ways to hold data, in increasing order of commitment: a dict for genuinely dynamic keys, NamedTuple for a small immutable record, @dataclass for a record with behaviour, a full class when invariants need defending. Reaching for the last one first is the usual mistake.

    Resources
    Learn
    • Python — NamedTuple
    • Python — dataclasses
    Practice
    • Model the same record all four ways and compare the line counts.
    • Pick the one that makes an invalid record impossible to construct.

  3. Encapsulation in practice — invariants

    The real job of a class is holding a rule true for its whole life: a rectangle's sides stay positive, an order's total always matches its lines. Validate in __init__ and in every setter, and the rest of the codebase can stop checking.

    Resources
    Learn
    • Python — property
    • Wikipedia — class invariant
    Practice
    • Name the invariant of a class you have written, out loud, then check the code enforces it.
    • Find a caller that validates something the class should have guaranteed.

  4. OOP smells

    God class — one class doing everything, usually named Manager or Utils. Deep hierarchies — four levels to find where a method is defined. Anaemic model — all getters and setters, with the logic sitting elsewhere. Each is a hint that behaviour and data drifted apart.

    Resources
    Learn
    • Refactoring Guru — code smells
    • Martin Fowler — Anemic Domain Model
    Practice
    • Find your largest class and list its responsibilities — stop when you reach three.
    • Find a getter that no caller uses and delete it.
