The protocols that let your own class behave like a built-in type — repr, equality, operators, iteration and with-blocks.

Dunder Methods — 6 topics

  1. __repr__ vs __str__

    __repr__ is for you — unambiguous, ideally something you could paste back into Python. __str__ is for the user. Define __repr__ first: print() falls back to it, and without one every debug session shows <object at 0x7f…>, which tells you nothing.

  2. __eq__ and __hash__ together

    Define __eq__ and Python sets __hash__ to None, making your objects unhashable — no sets, no dict keys. Equal objects must hash equal, so the two have to be written as a pair, over the same fields. @dataclass(frozen=True) does both correctly for free.

  3. Operator overloading

    a + b calls a.__add__(b), and returns NotImplemented rather than raising so Python can try b.__radd__(a) before giving up. Worth doing for genuine value types — money, vectors, durations — and a liability everywhere else.

  4. The iterator protocol

    __iter__ returns an iterator and __next__ produces values until it raises StopIteration — that is literally all a for loop does. Implementing __iter__ as a generator gets you both for one line, which is almost always the right move.

  5. The context manager protocol

    __enter__ and __exit__ are what with calls. __exit__ runs even when the block raises, which is why with is the correct way to guarantee cleanup — and returning True from it swallows the exception, which is almost never what you want.

  6. __len__, __getitem__, __contains__

    Implement these and your class starts behaving like a built-in container — len(x), x[0], for i in x, y in x. __getitem__ alone gets you iteration for free, which is the oldest trick in the data model.
