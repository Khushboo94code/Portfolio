Fundamentals — 6 topics

  1. Classes, objects and self

    A class is the blueprint, an object is one thing built from it. self is not magic — Python passes the object in as the first argument, which is why every method declares it and why Employee.greet(e1) and e1.greet() are the same call.

    • Add an attribute to one instance only, then check it is missing from a second instance.

  2. Encapsulation

    Bundling data with the methods that are allowed to change it, so a class can protect its own invariants. Python enforces none of this with keywords — it uses naming conventions plus @property when a rule genuinely has to hold.

    • Rename an internal attribute and confirm no caller had to change.

  3. Abstraction

    Exposing what something does and hiding how. A caller should be able to use send(message) without knowing whether it is SMS, email or a queue underneath — which is what makes the implementation replaceable later.

  4. Inheritance

    One class taking another's attributes and methods, to express "is-a". Useful and badly overused: it is the tightest coupling in OOP, because a subclass depends on its parent's internals, not just its interface.

  5. Polymorphism

    The same call doing the right thing for different types. Python gets most of this from duck typing — if the object has the method, it works — rather than from a shared base class, which is why len() works on anything that implements __len__.

    Resources

    • Implement __len__ on your own class and call len() on it.

  6. Composition over inheritance

    Preferring "has-a" to "is-a". A Car that has an Engine can swap engines at runtime; a Car that is an Engine cannot. Deep hierarchies are the single most common reason a codebase becomes rigid.
