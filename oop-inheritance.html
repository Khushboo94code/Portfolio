Inheritance & Polymorphism — 6 topics

  1. super() and cooperative inheritance

    super() does not mean “my parent” — it means “the next class in the MRO”, which is why it works with multiple inheritance and why hard-coding Parent.__init__(self) breaks it. A subclass that forgets to call it ends up with a half-initialised object.

  2. MRO and the diamond problem

    When a class has several parents, Python linearises them with C3 and walks that order left to right, depth-first but never visiting a class before its children. Class.__mro__ prints the answer, which is faster than reasoning about it.

    Resources
    Learn
    • Python — method resolution order
    • Wikipedia — multiple inheritance & the diamond problem
    • Michele Simionato — The Python 2.3 MRO — where C3 entered Python
    Practice
    • Build a diamond where two parents define the same method and predict the winner before printing __mro__.
    • Construct a hierarchy Python refuses to linearise and read the TypeError.

  3. Method overriding — and why there is no overloading

    A subclass redefining a method with the same name replaces it. Python has no overloading by argument count or type: defining the same name twice simply keeps the last definition, so the same effect comes from default arguments, *args, or dispatching on type inside one function.

  4. Abstract base classes

    abc.ABC plus @abstractmethod makes a class impossible to instantiate until every abstract method is implemented, turning “you forgot to write this” from a runtime AttributeError into an error at construction time.

  5. Duck typing and protocols

    If it has the method, it works — no base class required. typing.Protocol adds static checking to that idea, so a type checker can verify “anything with .read()” without forcing every implementation to inherit from you.

  6. Mixins and multiple inheritance

    A mixin is a small class that adds one capability and is never instantiated alone — TimestampMixin, SerialisableMixin. It is the one use of multiple inheritance that stays readable, because each mixin owns a narrow, non-overlapping slice of behaviour.
