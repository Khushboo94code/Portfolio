Python Mechanics — 6 topics

  1. __init__, instance vs class attributes

    __init__ runs after the object exists and fills it in — it is an initialiser, not a constructor. Anything assigned on self belongs to that one object; anything assigned in the class body is shared by every instance, which is a quiet bug when the shared thing is mutable.

  2. Instance, class and static methods

    Three method kinds, split by what they need. An instance method needs the object (self); a @classmethod needs the class (cls) and is the normal way to write alternative constructors; a @staticmethod needs neither and is really just a function that lives in the class for tidiness.

  3. Public, protected and private

    Python has no access keywords. One underscore is a convention meaning “internal, do not rely on this”; two underscores trigger name mangling to _ClassName__attr, which prevents accidental collisions in subclasses but hides nothing — the value is still reachable if you spell it out.

  4. @property — computed and validated attributes

    The actual answer to “where are the getters and setters”. A property keeps the attribute syntax callers already use while running code on access or assignment, so validation can be added to a live class without changing a single call site.

  5. @dataclass — removing the boilerplate

    For classes that mostly hold data, @dataclass generates __init__, __repr__ and __eq__ from the annotations. frozen=True makes instances immutable and hashable. The trap is a mutable default — use field(default_factory=list), never = [].

  6. __slots__ and object memory

    By default every instance carries a __dict__, which is flexible and not free. __slots__ fixes the attribute set and drops the dict, cutting memory noticeably when you hold millions of small objects — and blocking the attribute typo that would otherwise silently create a new field.
