Foundations — 5 topics

  1. What an OS does

    It manages hardware so your program does not have to, and shares it safely between processes that do not know about each other. Four jobs: processes, memory, files and devices — every OS topic is one of those four.

  2. Kernel space vs user space

    The kernel runs privileged and can touch hardware; your code runs unprivileged and cannot. That single boundary is why one buggy program cannot crash the machine or read another process’s memory — and why crossing it costs something.

  3. System calls

    The doorway between the two worlds. open, read, write, fork, execve — every interesting thing your program does eventually becomes one of these. A system call is far more expensive than a function call, which is why buffering exists.

    Resources
    Learn
    • syscalls(2) — the complete list
    • strace(1) — watch them happen live
    • OSTEP — the process API chapters
    Practice
    • Run strace python -c "print(1)" and count how many system calls that takes.
    • Find the write call that actually prints your output.

    • logging — logging bottoms out in write() system calls

  4. Interrupts, traps & exceptions

    How the CPU gets told something happened. A hardware interrupt is a device saying "I am ready"; a trap is your program deliberately calling into the kernel; an exception is something going wrong. All three switch to kernel mode and run a handler.

  5. Boot, init & the process tree

    From firmware to a login prompt: the bootloader loads the kernel, the kernel starts init (systemd on most Linux), and everything else descends from it. Every process except the first has a parent, which is what makes the process tree a tree.
