Memory Management — 5 topics

  1. The address space

    Text, data, BSS, heap and stack — laid out so the heap grows up and the stack grows down. Knowing this layout is what makes a stack overflow, a memory leak and a segmentation fault three different, diagnosable things.

  2. Virtual memory & paging

    Each process gets its own virtual address space, translated to physical frames through a page table. This gives isolation, lets programs use more memory than exists, and makes shared libraries shareable — the single most important idea in operating systems.

  3. Page faults, TLB & replacement

    A page fault means the page is not resident — the kernel fetches it and resumes you. The TLB caches translations so the page table is not walked every access. When faults dominate real work, that is thrashing, and the machine grinds to a halt.

  4. Allocation & fragmentation

    How malloc finds you memory, and why freeing it does not always return it to the OS. External fragmentation leaves unusable gaps between allocations; internal fragmentation wastes space inside them. Paging solves the external kind.

  5. Stack vs heap

    The stack is fast, automatic and scoped to a call; the heap is manual, flexible and outlives the function. In Python you never call malloc, but every object is on the heap and only references sit on the stack — which is exactly why mutable default arguments behave the way they do.
