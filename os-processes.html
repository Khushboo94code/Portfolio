Processes & Scheduling — 5 topics

  1. Process lifecycle & the PCB

    New, ready, running, waiting, terminated — and the kernel’s record of each one, the process control block, holding its registers, memory map, open files and state. A context switch is really just saving one PCB and loading another.

  2. fork, exec & process creation

    Unix creates processes by copying — fork duplicates the caller, and the child usually calls exec to replace itself with a different program. Copy-on-write makes the duplication cheap. This is exactly what Python’s multiprocessing does underneath.

  3. Context switching

    Saving one process’s registers and restoring another’s so both appear to run at once. It is not free — registers, the TLB flush, and cache pollution all cost — which is why thousands of threads perform worse than a handful plus async I/O.

  4. CPU scheduling algorithms

    FCFS, shortest-job-first, round robin, priority and multilevel feedback queues — and the trade they all negotiate: throughput versus latency versus fairness versus starvation. Interactive systems favour response time, batch systems favour throughput.

  5. IPC — how processes talk

    Isolated by default, so communication must be explicit: pipes, named pipes, message queues, shared memory, sockets and signals. Shared memory is fastest and reintroduces every synchronisation problem isolation had removed.
