Files, Storage & I/O — 5 topics

  1. Files, inodes & directories

    A file’s name is not the file. The inode holds the metadata and block pointers; a directory is just a table mapping names to inode numbers. That is why a hard link costs nothing and why deleting a file with an open handle does not free the space.

  2. File descriptors & redirection

    An open file is an integer index into a per-process table. 0, 1 and 2 are stdin, stdout and stderr — which is the whole mechanism behind shell redirection and pipes. Running out of them is the EMFILE error you have met.

  3. The page cache & buffered I/O

    The kernel caches file contents in free RAM, which is why the second read of a file is instant and why "free memory" on Linux looks alarmingly low and is not a problem. It also means a write returns before the data is on disk — fsync is what actually guarantees durability.

  4. Disk scheduling & SSDs

    FCFS, SSTF, SCAN and the elevator algorithm exist because seeking a spinning disk is expensive. On SSDs seek cost vanishes and different concerns appear — wear levelling, write amplification, and the fact that random reads are no longer catastrophic.
