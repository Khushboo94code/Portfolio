Tooling & Quality — 4 topics

  1. Environments & packaging

    One virtual environment per project so dependencies cannot collide, and a pinned lockfile so the versions you tested are the versions that deploy. uv is now the fast option; pip-tools and Poetry are the established ones.

    Resources
    Learn
    • Python Packaging User Guide
    • uv — very fast installs and resolution
    • venv
    Practice
    • Pin a project with a lockfile and rebuild it from scratch in a clean environment.

  2. Testing with pytest

    Plain asserts, fixtures for setup, parametrize for the same test over many inputs, and monkeypatch for isolating external calls. The design pressure matters as much as the coverage — untestable code usually has the wrong seams.

    Resources
    Learn

    • pytest — fixtures
    • unittest.mock
    Practice

  3. Linting, formatting & types

    Stop arguing about style by automating it: ruff for linting and formatting in one fast tool, mypy for type checking, and pre-commit so all of it runs before a commit rather than in review.

  4. Debugging & logging

    breakpoint() drops you into a debugger at any line, which beats scattering print statements. And logging with levels and structure beats printing entirely — the moment code runs somewhere you are not watching, prints are gone.
