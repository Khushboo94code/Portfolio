Patterns — 5 topics

  1. Caching with Redis

    The original use, and the Redis mechanics for it: SET key val EX for cache-aside with a TTL, jittered expiry so a thousand keys do not drop at once, SET … NX as the lock that stops a stampede, and caching a negative result so a miss is not re-queried forever. The strategies and failure modes themselves are in HLD → Caching.

  2. Rate limiting

    A counter per key with an expiry is a fixed-window limiter in two commands. Sliding windows use a sorted set of timestamps; token buckets store tokens and a refill timestamp. Doing it in a Lua script keeps it atomic across many app instances.

  3. Sessions & shared state

    Moving session state out of the app process is what makes horizontal scaling possible — any instance can serve any request because the session lives in Redis, not in local memory. Carts, feature flags and short-lived tokens follow the same pattern.

  4. Queues & pub/sub

    Two different tools. Lists give a durable work queue consumed by one worker; pub/sub is fire-and-forget broadcast with no persistence — a subscriber that is offline simply misses the message. Streams sit between them with acknowledgement and replay.

  5. Distributed locks

    One instance at a time across many processes — SET key val NX EX 30 acquires, a matching random value proves ownership on release. Essential for "only one scheduler runs" and genuinely subtle: a lock that expires mid-work is worse than no lock.
