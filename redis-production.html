Production — 5 topics

  1. Memory & eviction policies

    Redis lives in RAM, so maxmemory plus an eviction policy is not optional. allkeys-lru for a pure cache, volatile-lru when some keys must never be evicted, and noeviction — which starts refusing writes — when you are using it as a database.

  2. Replication & Sentinel

    A replica keeps a copy and serves reads; Sentinel watches the primary and promotes a replica when it fails. Replication is asynchronous, so a failover can lose the most recent writes — which is fine for a cache and not for a queue.

  3. Redis Cluster & sharding

    Beyond one machine’s memory, Cluster shards the keyspace across nodes by hash slot. The catch: multi-key operations only work when keys land on the same node, which is what hash tags are for — and why cluster changes how you design keys.

  4. Monitoring & slow commands

    The metrics that matter: hit rate, evicted keys, memory usage and connected clients. SLOWLOG catches commands that blocked the server, and because Redis is single-threaded, one slow command is everyone’s problem.

  5. Security & operations

    Default Redis has no password and binds to all interfaces, which is how instances end up mining cryptocurrency for strangers. Require authentication, bind to a private network, rename or disable dangerous commands, and never expose it to the internet.
